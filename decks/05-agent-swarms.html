part one

What a swarm actually is

Not a crowd. A graph.

≈3 min in.
from loop to graph

One agent is a while-loop. A swarm is a graph of them.

  • Single agent: model → tool → result → model … until done. Context grows, roles blur, retries restart everything.
  • Swarm: each agent = node with own prompt, tools, model, budget; edges = who talks to whom; shared state = the contract between them.
  • Two canonical styles: handoff ("you take over", OpenAI Swarm→Agents SDK) vs orchestrator-workers ("you report to me", LangGraph/Anthropic research system).
  • Both compile to the same thing: a state machine with LLM nodes — which is exactly why it's debuggable.

CrewAI popularized "role-based crews" (sequentials/hierarchical); AutoGen group-chat = free-form handoff network (powerful, hard to bound). The industry converged on graphs because free-form chat between agents is non-deterministic and expensive.

Configuring with graphs

State, nodes, edges — plus the two production features: interrupts and checkpoints.

≈8.5 min in.
the graph contract · LangGraph

State + nodes + conditional edges

class State(TypedDict):
    plan: Plan | None
    findings: Annotated[list[Finding], operator.add]  # parallel fan-in!
    draft: str | None
    verdict: Verdict | None
    revisions: int

def triage(s):   # cheap router model
    plan = router.with_structured_output(Plan).invoke(...)
    return {"plan": plan}

def fanout(s):  # dynamic edges: one Send per sub-question
    return [Send("researcher", {"q": q}) for q in s["plan"].sub_questions[:6]]

g = StateGraph(State)
g.add_node("triage", triage, ...)        "researcher" = worker w/ tools + RetryPolicy
g.add_edge(START, "triage")
g.add_conditional_edges("triage", fanout)            # ── fan-out
g.add_edge("researcher", "synthesize")               # ── fan-in
g.add_edge("synthesize", "verify")
g.add_conditional_edges("verify", lambda s:
    "finalize" if s["verdict"].passed or s["revisions"] >= MAX
    else "synthesize")                               # cyclic: bounded retry
app = g.compile(checkpointer=InMemorySaver())         # resumable state

Why each piece

  • Typed state = the API between agents; no prose "telephone"
  • Reducers (operator.add) merge parallel branch writes deterministically
  • Send() = runtime fan-out: N branches, one per question
  • Structured outputs (Pydantic) — routing decisions, not paragraphs
  • Checkpointer = resume/interrupt/time-travel; crash ≠ restart-from-zero
Real code from research/examples/deep_research_swarm.py (langgraph 1.2.x). Key subtlety: cyclic graphs need explicit termination (revisions cap) or you get token storms. Checkpointer also powers HITL: state persists per thread id.
human gates + the other stack

Interrupts: the graph pauses for a human

def approve(s):
    ok = interrupt({"plan": s["plan"]})   # graph stops here
    return {"plan": ok}                    # ...resumes with human edit

result = app.invoke(q, {"configurable": {"thread_id": "t1"}})
result = app.invoke(Command(resume={"sub_questions": [...]}),
                    config)                 # human edits the plan mid-run
Put interrupts before anything irreversible or expensive: sending, buying, deleting, spawning 20 sub-tasks.

OpenAI Agents SDK: same graph, declarative

triage = Agent("triage", instructions=...,
    handoffs=[refund, tech, escalate])   # handoffs = edges
guard_in = InputGuardrail(guardrail_function=no_secrets)
result = runner.run(triage, user_msg,
    guardrails=[guard_in])
# handoff = transfer_of_control (edge)
# as_tool = orchestrator pattern (worker)
# sessions = thread-scoped state
# tracing = built-in (spans per agent/tool)

OpenAI Agents SDK docs (local: research/_raw/oa_*.txt): handoffs-as-tools, guardrails, sessions, tracing.

Two config philosophies: LangGraph = explicit graph (you draw it); Agents SDK = agents+handoffs that implicitly form a graph (the model routes). MAF (MS AutoGen+SK successor) similar with typed orchestration; CrewAI = role YAML on top of LangGraph-ish engine.

Patterns you'll reuse in every swarm you build.

four reusable patterns

Composition patterns

① Orchestrator–workers + artifact passing

Lead plans & reviews; workers search/build in their own context; big outputs go to a filesystem/artifacts, only references return — kills the telephone game and the token bill (Anthropic eng blog).

② Generate → verify loop (evaluator-optimizer)

Verifier with a rubric returns {passed, missing[]}; missing gaps drive a targeted second fan-out — bounded by MAX_REVISIONS. Quality jump is real; unbounded loops are the failure mode.

③ Parallel fan-out with reducers

Send() N branches; operator.add reducers merge; wall-clock shrinks near-linearly (−90% on research tasks per Anthropic) — but each branch pays tokens; cap fan-out (SUBQUESTION_CAP).

④ Human gates on irreversible edges

interrupt() before send/buy/delete/spend; checkpointer resumes days later. This is the difference between a demo and a deployable.

These four tiles map 1:1 to code sections in the example file. Pattern ①'s "artifacts not prose" detail is straight from Anthropic's lessons: subagents write outputs to external stores, pass lightweight refs.

Failure modes & production

What actually breaks — from the engineering post-mortems.

≈24.5 min in.
the post-mortem slide

Six ways swarms die (all documented)

  • Token storm. Multi-agent ≈15× chat tokens; naive fan-out multiplies. Caps + artifact-passing + cheap router models.
  • Telephone game. Summaries of summaries lose fidelity → artifacts + typed state, not prose chains (Anthropic's #1 lesson).
  • Coordination ambiguity. "Who was doing that?" → explicit state ownership; one writer per field, reducers for the rest.
  • Premature complexity. Simple tasks given swarms waste 5–10× (our estimate from the 4×/15× token ratios) — route: single agent default, escalate to swarm by task score.
  • Error compounding in cycles. Unbounded retry loops amplify; verify-then-target gaps, cap revisions, checkpoint good states.
  • Safety surface ×N. Every agent with tools is an injection target (talk 04): least-privilege each, guard the edges between them.
Production checklist: budgets · turn caps · sandboxed execution · per-agent tracing · golden-task evals in CI · kill-switch · resumable checkpoints.
These six map onto MAST (arXiv:2503.13657): 14 failure modes in 3 categories — specification/design, inter-agent misalignment, verification & termination — annotated over 1,600+ traces from 7 frameworks. Same paper's warning: MAS gains on benchmarks are "often minimal".
All six are from Anthropic's eng blog + Cognition's "Don't Build Multi-Agents" counterpoint + the MAST failure taxonomy (arXiv:2503.13657, 14 modes / 3 categories, κ=0.88). Cognition's argument (context-sharing matters, don't parallelize ambiguous work) is the honest counterweight to the 90.2% headline — mention it, it scores credibility points. If asked "how do you know you got them all": you don't, MAST is the closest thing to a census.

  • Artifacts, not prose between agents; interrupt() before anything irreversible.

  • Start single-agent; escalate to swarm only when the task decomposes cleanly.
